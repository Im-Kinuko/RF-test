# 03: 光耦單段 RUN

**What to build:** 研究人員按「跑一段」（方向、20 筆、指定間隔 0／1／5／10 ms），Arduino 自行以 `micros()` 依「上一筆動作完成後休息 gap_ms」連送 20 筆，期間不輸出序列資料；完成後一次回傳逐筆時間戳與 `DONE`。Unity 顯示預期面板速度，研究人員輸入實際讀數後立即看到該段推算掉包數，並寫入每段 CSV。

## 完成紀錄（2026-11-21）

- 核心：`RunSegment(方向, 筆數, 間隔, 起點速度, now)`、`SubmitReading(面板速度)`、`SegmentRun`（時間戳、平均／最大實際間隔、`ReportShort`、`TimedOut`）、`SegmentResult`（預期／實際變化、掉包數）。
- 段逾時 = 筆數 ×（韌體回報的 `action_ms` + 間隔）× 2 + 2 秒；未回報 `action_ms` 時保守採 500 ms。
- `PanelSpeedInput`：接受「1」「1.0」；沒有小數點且 ≥ 10 的整數自動除以 10（「27」→ 2.7），因此 10～12 km/h 須輸入「10.0」；超出 0.1～12.0 拒絕。
- `SegmentCsvWriter`：每段一列、寫入即 flush；介面以 UTF-8 BOM 寫到 `TestLogs/segments_*.csv`。
- 韌體 `StressTest_Opto` v0.2.0：`RUN,<UP|DOWN>,<n>,<gap_ms>`（n ≤ 32），以 `micros()` 控制間隔；ACK 送完才開始計時；時間戳存 RAM、整段結束才回傳；期間收到的指令行一律回 `ERR,BUSY`；結束時所有腳位拉回 LOW；`READY` 增加 `action_ms=120`。
- 介面：方向、間隔（0／1／5／10 ms）、筆數、目前面板速度；執行進度條；大字顯示預期速度，輸入框自動取得焦點、Enter 送出；顯示掉包數、回報筆數、實際間隔與 CSV 路徑。
- 審查修正：
  - `micros()` 約 71.6 分鐘溢位，間隔改以 2^32 取模相減。
  - 段逾時後鎖住下一段，直到收到遲到的 `DONE` 或韌體重新開機的 `READY`，避免舊回報混入新段；介面顯示等待提示。
- 驗證：EditMode 44/44 通過；韌體 avr-g++ 語法檢查無警告。尚未接 Nano 實測 0 ms 間隔下的時間戳。
