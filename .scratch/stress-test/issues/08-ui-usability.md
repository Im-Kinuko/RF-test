# 08: 介面易用性整理

**What to build:** 研究人員站在跑步機旁也能一眼看懂下一步：畫面分為上方狀態列（連線燈、入口、目前輪次與條件）、中央「現在要做的事」大卡片（單一主要按鈕或數字輸入框＋預期值）、右側條件矩陣與進度；字級放大、全繁體中文。

**Blocked by:** 06, 07

**Status:** done

- [x] 三區版面在 1920×1080 與 1280×720 下都不重疊、不需捲動
- [x] 任一狀態只有一個主要動作被強調；不可用的按鈕停用而非隱藏
- [x] 緊急停止按鈕在所有狀態可見
- [x] 所有提示、錯誤訊息為繁體中文
- [x] 介面只呈現測試核心狀態與轉發輸入，不含判定邏輯

## 完成紀錄（2026-11-22）

- 版面分成三區，位置和大小都依視窗尺寸計算：
  - 上方狀態列：連線燈號、狀態文字、COM port 與韌體參數，右邊是「中斷連線」和紅色「緊急停止（空白鍵）」。
  - 左側（約 56% 寬）：「現在要做的事」。
  - 右側：條件矩陣、每條件輪數與每段筆數、整體排程、開啟紀錄資料夾。
  - 三個面板都用實心深色底，避免場景天空盒透出來、降低文字對比。
- 縮放規則：以 1920×1080 為 1 倍等比縮放，最小縮到 0.8 倍（1280×720 實際是 0.8 倍），文字和欄寬用同一個比例。中文字底部會超出依西文計算的行高，所以標籤設成不裁切。
- 左側卡片依狀態只顯示一件事，綠色主要按鈕各只有一顆：
  - 未連線：「3. 連線」
  - 入口不符或逾時：「中斷連線，重新選擇」
  - 閒置：「開始下一輪」
  - 輸入面板速度：「確認（Enter）」
  - 確認畫面：「確認，開始下一段（Enter）」
  - 預熱讀數不符：「重新預熱」
  - 總結：「跑帶已停止，回到設定」
  - 其他按鈕都是次要的灰色按鈕。
- 停用與隱藏：暫時不能用的按鈕一律停用，不隱藏。例如矩陣格子在測試進行中或未連線時會停用，單發和手動單段在非 Ready 狀態也會停用。單發和手動單段收在「展開手動工具」裡，預設收起；這是研究人員自己選擇收合，不是因為不能用才隱藏。
- 文字：狀態列的所有狀態都有中文說明。原本預設情況會直接顯示 enum 名稱，現在已經沒有了。
- 介面只負責呈現核心狀態、轉發操作，判定邏輯維持在 Core。
- 新增驗收工具：
  - `StressTest.Editor` 的 `StressTestBuild.BuildWindows`：在 batchmode 下建置只含 StressTest 場景的 Windows 執行檔。
  - 執行檔加上參數 `-stresstest-screenshot <路徑>` 啟動時，會在第 30 格截圖、第 60 格結束。
- 驗證：
  - 建置 Windows 執行檔後，在 1920×1080 和 1280×720 各截一張圖（`Docs/screenshots/idle_*.png`），三區沒有重疊，也不需要捲動。這兩張只涵蓋未連線的畫面。
  - 連線後的各個狀態（預熱、輸入、確認、總結）需要接上 Arduino 才看得到，尚未截圖。這些狀態的內容比未連線畫面少，且左側面板保留捲動作為保險。
  - Unity EditMode 97/97 通過；程式碼審查沒有發現問題。

## 補充紀錄（2026-11-26）：所有畫面截圖

- 新增 `SimulatedArduino`（模擬韌體）與版面導覽模式 `-stresstest-tour <資料夾>`：不接硬體也能自動走過 25 個畫面並截圖，存放在 `Docs/screenshots/ui/`，逐張說明寫在 `Docs/UI-Screens.md`。
- 截圖檢查時發現並修正四個問題：
  - 狀態燈號原本只是黑色方塊，現在改畫實心彩色圓點。
  - 進度條的填色看不出來，改成藍色。
  - 預期速度低於最低速度 1.0（或高於 12.0）時，原本沒有提示，現在會說明面板會停在極限值。
  - 單發區底下原本會顯示手動單段的 RUN 回報，現在只顯示單發的回報。
- 原本「連線後各狀態待實機確認」的部分，已經用模擬韌體確認版面；實機操作仍列在票 09。
