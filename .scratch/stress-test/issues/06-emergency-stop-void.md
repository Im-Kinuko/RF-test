# 06: 緊急停止與作廢

**What to build:** 任何狀態下研究人員按空白鍵或大紅色「緊急停止」，系統立即要求 Arduino 中斷迴圈並送停止，該輪進入總結並標記為作廢；研究人員也能在一輪結束後手動作廢並填原因。作廢輪的原始資料保留但不計入矩陣進度。

## 完成紀錄（2026-11-22）

- 韌體（光耦、RF 都升到 v0.3.0）：
  - `RUN` 執行期間會逐行讀取序列埠，收到 `ABORT` 就中止。檢查點在每一筆動作完成後，以及休息間隔內，所以不會切斷正在進行的按壓或發射。中止後最慢一筆內就會停下。
  - 中止後回傳已完成那幾筆的 `T`，再加上 `ABORTED,<n_sent>`。
  - 沒有在跑 `RUN` 時收到 `ABORT`，回 `ABORTED,0`。
  - 其他在 RUN 期間收到的指令行，照舊在段結束後回 `ERR,BUSY`。
  - 光耦版不論是正常完成還是中止，結束時都會執行 `releaseAll()` 把腳位全部拉回 LOW；`ONE` 的按壓本身也會在結束時拉回 LOW。
- 核心：
  - `StressTestSession.Abort()`：段執行中送出 `ABORT`，收到 `ABORTED` 後回到 Ready，該段標記 `Aborted`。逾時後還在等遲到 DONE 的段也一樣可以中止（審查後修正）。
  - `StressTestSession.DiscardSegment()`：放棄正在等待輸入讀數的那一段，回到 Ready。
  - `TestRound.EmergencyStop()`：
    - 段執行中：先 `ABORT`，等收到 `ABORTED`，再送停止。
    - 其他狀態：直接送停止。
    - 2 秒內沒收到 `ABORTED`，本輪判定失敗，畫面提示「請立即按跑步機上的停止鍵」。
    - 啟動指令還沒 ACK 時按下，要等啟動和停止兩個 ACK 都收到。
  - `TestRound.Finish(voidReason)`：研究人員離開總結畫面時才寫入每輪 CSV 的那一列。帶原因就是手動作廢；緊急停止或失敗的輪次一律記為作廢，原因分別是「緊急停止」或失敗原因。這個方法只會寫一次。
- 每輪 CSV：`status` 欄的值是 `completed` 或 `voided`，另外新增 `void_reason` 欄。原因中的半形逗號會換成全形，換行換成空白。
- 介面：
  - 連線狀態下方一直顯示紅色「緊急停止（空白鍵）」按鈕。
  - 手動單段也可以緊急停止：先中止，回到 Ready 後補送停止。
  - 總結畫面可以填寫作廢原因後按「作廢此輪」。游標在作廢原因欄位時，空白鍵不會觸發緊急停止（審查後修正）。
  - 停在總結畫面時中斷連線或關閉 Unity，會自動補寫每輪那一列。
- 驗證：
  - Unity 6000.6.10f1 batchmode EditMode 86/86 通過。
  - 兩支韌體用 avr-g++ 做語法檢查，沒有警告。
  - 「作廢不計入進度」目前做到的程度：每輪 CSV 的 `status` 欄會標成 `voided`。真正計算條件進度要等票 07 的矩陣。
  - 尚未接硬體實測。
