# 05: 完整一輪

**What to build:** 研究人員選入口、間隔與總次數（40／80／120）後按「開始」，系統自動依序完成一輪：送啟動並倒數 5 秒 → 每秒一次共 9 次預熱加速 → 請輸入面板速度（預期 1.0）→ 依總次數產生每段 20 筆、加減交替的多段（1.0 ↔ 3.0），每段後輸入面板速度 → 送停止 → 顯示本輪總結。所有結果寫入逐筆、每段、每輪三份 CSV。

## 完成紀錄（2026-11-22）

- 核心新增：
  - `RoundPlan`：依總次數與每段筆數切段，加減交替，記錄每段理論起訖速度。
  - `RoundConfig`：預熱次數 = (起點 1.0 − 開機 0.1) ÷ 0.1 = 9；倒數 5 秒、預熱間隔 1 秒、單發 ACK 上限 3 秒。
  - `TestRound`：整輪狀態機，由介面每格呼叫 `Tick`。
  - `RoundSummary`：總掉包、總送出、預熱與終點讀數、旗標、整輪實際間隔。
  - `RoundCsvLog`：逐筆、每段、每輪三份 CSV。
- 流程：送啟動並等 ACK → 倒數 5 秒 → 每秒單發加速 9 次（依固定時間軸排程，畫面延遲不會累加）→ 輸入預熱讀數 → 確認 → 各段 → 送停止並等 ACK → 總結。每次單發都要等到 ACK 才送下一次；收到 ERR 或 3 秒沒有回應，本輪就停在 Failed 並寫明原因。
- 輸入與撤銷：輸入面板速度後先進入確認畫面，顯示這一段的掉包數與旗標。Enter 確認後往下走，Esc 退回去重新輸入；撤銷不影響已經開始的段。
- 預熱讀數不符（與 1.0 差 0.05 以上）時有兩個選擇：「重新預熱」只用單發補足差額，再請研究人員確認一次；「以實際速度為起點繼續」則把實際讀數當成第一段的起點。
- 每段都以上一段的實際讀數為起點。`SegmentResult.PossiblyClamped` 代表「起點 + 預期變化」超出 0.1～12.0。
- 審查修正：某一段逾時後，下一段不再直接讓整輪失敗，改為進入 `WaitingForLateDone`，等收到遲到的 DONE 再自動開始；超過 30 秒還沒收到才判定失敗。
- CSV 變更：每段 CSV 新增 `round_id`、`segment_index`、`possibly_clamped` 三欄。手動單段改寫到 `manual_segments_*.csv`，兩欄留空。完整一輪會產生 `commands_*.csv`、`segments_*.csv`、`rounds_*.csv`，都是 UTF-8 BOM，寫入即 flush。
- 介面：主畫面新增「完整一輪」區塊，可選間隔、總次數、每段筆數。測試進行中只顯示目前步驟的大卡片，包括倒數、預熱進度、輸入框、確認、讀數不符時的兩個選擇、執行進度、總結，以及「跑帶已停止，回到設定」按鈕。連線中斷時，本輪會標示為未完成。
