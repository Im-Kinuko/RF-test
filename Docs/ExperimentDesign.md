# 實驗設計

> 版本：2026-11-28。
> 這份文件說明實驗要做什麼、怎麼做、畫面長怎樣、怎麼看結果。程式和資料欄位的細節在 [README](../README.md)。
> 目前沒有任何實機結果。文中的時間數字都是推算值。

## 1. 這個實驗在做什麼

電腦叫跑步機加速或減速很多次。我們比對兩個數字：**送了幾次**，以及**跑步機動了幾格**。如果少了，就查是在哪裡少的。

要回答兩個問題：

1. **掉多少？** 用光耦和 RF 控制跑步機，各有多少指令沒有作用？
2. **掉在哪裡、為什麼？** 指令是在哪一段不見的？

這是機器對機器的測試，**沒有受試者**。研究人員只負責按開始、看面板和錄影、記下異常。跑帶上不站人。

## 2. 名詞

| 名詞 | 意思 |
|---|---|
| 指令 | 一次加速或一次減速。成功時速度變化 0.1 km/h（一格） |
| 入口 | 控制跑步機的方式。**光耦**（V1，代替手指按面板）或 **RF**（V2，代替遙控器） |
| 送法 | 電腦用什麼節奏送指令。有 A、B、C 三種，另有 RUN 對照 |
| gap | 兩個指令之間設定的等待時間 |
| 總次數 | 一輪要送的指令數：40、80 或 120 |
| 段 | 同一方向的 20 個指令 |
| 輪 | 加速段和減速段輪流，直到送滿總次數（2、4 或 6 段） |
| 轉向點 | 一段結束、換方向的那一刻。加速段結束是最高點，減速段結束是最低點 |
| 掉包 | 送出的指令沒有反映在跑步機上 |

## 3. 指令走過哪裡，怎麼知道掉在哪

```
①電腦  ──USB──▶  ②③Arduino  ──▶  ④光耦／RF 模組  ──▶  ⑤跑步機
```

| 檢查點 | 要問的問題 | 現在量得到嗎 |
|---|---|---|
| ① | 電腦送了幾個？ | 可以（A 送法） |
| ② | Arduino 收到幾個？ | 可以（A 送法） |
| ③ | Arduino 做了幾個？ | 可以 |
| ④ | 光耦或 RF 有沒有真的送出訊號？ | **不行**，缺量測硬體 |
| ⑤ | 跑步機動了幾格？ | 可以。A 看轉向點和最後速度；RUN 看每段結束的面板 |

相鄰兩個數字相減，就知道少在哪裡：

| 畫面上的名稱 | 算法 | CSV 欄位 |
|---|---|---|
| 序列端少 | 電腦送出 − Arduino 收到 | `link_lost` |
| 跑步機端少 | Arduino 做了 − 面板動的格數 | `treadmill_missing` |

**例子**：電腦送 20，Arduino 收到 19、做了 19，面板動 17 格。結果是序列端少 1，跑步機端少 2。

兩個注意事項：

- 「跑步機端少」是**負數**時，表示跑步機動得比指令多。
- 因為量不到 ④，「跑步機端少」分不出是**模組沒送出訊號**，還是**跑步機沒收下**。

## 4. 四種送法

| 送法 | 怎麼送 | 中間停不停 | 狀態 |
|---|---|---|---|
| **A 等回覆** | 電腦送一個，等 Arduino 回「做完了」，停 gap，再送下一個 | **整輪不停** | 程式完成，**還沒實機測** |
| **B 固定間隔** | 電腦每隔固定時間送一個，不等回覆 | 整輪不停 | 還沒做 |
| **C 原版重現** | 電腦約每秒送一個，Arduino 照原版系統的方式處理 | 整輪不停 | 還沒做 |
| **RUN 對照** | 電腦只說一次「做這一段」，Arduino 自己連續做 | 每段停下來讀面板 | 程式完成，**還沒實機測** |

A、B、C 用**同一套指令順序**（加 20、減 20 輪流），差別只在怎麼送，這樣才能比較。
RUN 對照目前仍是舊流程（每段停下來），因為 Arduino 程式一次只能送一個方向。

### 為什麼要整輪不停

如果每 20 個就停下來記錄，120 次只是「連續 20 個」做 6 遍。Arduino 和跑步機每次都能休息，測不出連續壓力。整輪不停，40、80、120 次才代表**連續**做多久。

### A 送法要注意

- 「做完了」只代表 Arduino 做完動作。它**不代表**跑步機收到。
- 電腦**不重送**沒有回覆的指令。重送會改變次數。
- **實際停的時間比 gap 長。** 實際時間 ＝ 回覆傳回電腦 ＋ 電腦處理 ＋ gap ＋ 下一個指令傳過去。光是傳輸約 4.5 ms，另加 USB 延遲（還沒量）。
- 論文要寫**量到的時間**（`gap_us`），不能只寫設定值。
- 換方向時沒有多停。換方向那一次的等待時間也有記錄。

收送的細部規則（逾時、壞掉的指令、重開機）見 [README 的 A 送法收送規則](../README.md#a-送法的收送規則)。

### B 送法的打算

- 間隔暫定 1000、500、350、150、100、10 ms。
- 光耦做一個指令約 120 ms，RF 約 340 ms。送得比這更快，指令會在 Arduino 裡排隊，排滿就掉。
- 排滿會掉是預料中的事。要看的是：掉包是否只發生在序列端，跑步機端有沒有另外掉。

### C 送法的打算

- RF 原版：指令太密時 Arduino 直接略過（800 ms 和 1000 ms 的冷卻）；排隊中的指令會被清掉；電腦不看回覆。
- 光耦原版：沒有冷卻；指令排隊時，按鍵幾乎沒有放開的時間。
- 傳輸速度用原版的 9600。
- Arduino 每略過一個指令，要記下原因。
- 手上沒有光耦版的感測控制程式，所以它原本的送出節奏無法確認。

## 5. 測哪些條件

A 送法的條件：

| 項目 | 內容 | 數量 |
|---|---|---|
| 入口 | 光耦、RF | 2 |
| gap | 0、1、5、10 ms | 4 |
| 總次數 | 40、80、120 | 3 |
| 每個條件重複 | 3 輪 | 3 |
| **合計** | | **72 輪** |

整個過程保持不變：跑步機、Arduino、接線、RF 天線位置和距離（拍照記下）、每段 20 個、單個指令的動作方式。

速度範圍：

| 送法 | 起點 | 來回範圍 | 上下還剩幾格 |
|---|---|---|---|
| A | 2.5 | 2.5 ↔ 4.5 | 上面到 6.0 剩 15 格，下面到 1.0 剩 15 格 |
| RUN 對照 | 2.0 | 2.0 ↔ 4.0 | 上面剩 20 格，下面剩 10 格 |

A 從 2.5 開始，因為整輪不停時，掉包造成的偏移會一直累積，需要上下都留空間。

其他送法的輪數：RUN 對照 72 輪（選做）、B 暫定 36 輪、C 暫定 10 輪。

- 工具會排順序，光耦和 RF 輪流先做。
- 工具**沒有打亂** gap 和總次數的順序。電池、溫度、干擾可能隨時間改變，分析時要看每輪的時間。
- 時間不夠時，先不做 RUN 對照，再不做 80 次。論文要寫明省了什麼、為什麼。

## 6. 一輪怎麼做（A 送法）

整體順序：

```
開始 → 啟動、等 5 秒 → 預熱 15 次到 2.5 → 確認起點 →【開始錄影】
→ 整輪連續送出（不用操作）→ 輸入最後速度 → 程式停止跑步機
→ 看影片，輸入每個轉向點 → 核對結果 → 離開本輪
```

| 步 | 畫面上看到 | 你要做什麼 |
|---|---|---|
| 1 | 「下一輪（A）：…」 | 架好手機錄影。按「開始下一輪」 |
| 2 | 「已送出啟動，等跑帶穩定」 | 等 |
| 3 | 「預熱加速：0／15」往上數 | 等 |
| 4 | 「請看面板，預期 2.5 km/h」 | 輸入面板數字，按 Enter |
| 5 | 「確認後會連續送出…請先開始錄影」 | **開始錄影**，再按 Enter |
| 6 | 「連續送出中：第 1／6 段（加速）」 | 不要操作。注意跑步機。有異狀按空白鍵 |
| 7 | 「整輪送完了，跑步機還在轉」 | 輸入面板現在的速度，按 Enter 兩次。跑步機會停。之後可按 Esc 退回來改 |
| 8 | 「看錄影：轉向點 1／5」 | 看影片，找最高點或最低點，輸入，按 Enter |
| 9 | 「請核對各段結果」 | 沒問題按 Enter。打錯按 Esc 回去 |
| 10 | 「本輪完成：總掉包…」 | 有問題就寫原因作廢；沒問題按「跑帶已停止，回到設定」 |

每個畫面的完整說明在 [README 的操作流程](../README.md#操作流程)。

轉向點的數量：40 次 1 個、80 次 3 個、120 次 5 個。最後速度另外在第 7 步輸入。

**怎麼算每一段掉幾個**：例如起點 2.5，第 1 段加速 20 個，最高點只到 4.3，代表掉 2 個。第 2 段減速 20 個，應該到 2.3；如果停在 2.4，代表掉 1 個。每一段都從**上一個實際讀數**算起。

**RUN 對照的差別**：起點 2.0、預熱 10 次；每段送完就停下來輸入面板數字，不用看影片找轉向點。

### 什麼時候作廢一輪

- 有人碰到跑步機、看錯面板、Arduino 重開機、出現「可能觸底／觸頂」。
- 指令沒有全部送出（提早結束、緊急停止、中斷連線）：程式**自動作廢**。
- **轉向點看不清楚**：按「讀不到，作廢此輪」。**不要猜。**
- **指令遺失或沒回覆不要作廢**，那是要收集的資料。

作廢的輪次不算掉包率，但紀錄保留，查原因時用。

### 安全

- 任何時候按**空白鍵**緊急停止。確認最後速度之前按，這一輪作廢；之後按只會再送一次停止。
- 一輪進行中不能按「中斷連線」。拔 USB 或關程式時，程式只能盡量送停止，**要確認跑帶已停**。
- 停止指令沒有回覆時畫面會提醒，直接按跑步機上的停止鍵。

## 7. 看到結果怎麼判斷

| 看到什麼 | 少在哪裡 | 接著查什麼 |
|---|---|---|
| 序列端少大於 0，或有壞掉的指令（`rejected`、`arduino_bad`） | 電腦到 Arduino | USB 線、傳輸速度、有沒有別的程式占用序列埠 |
| 有指令沒回覆（`no_reply`），但序列端沒少 | 回覆的路上 | 回覆太慢或遺失 |
| Arduino 重開機（`rebooted`） | Arduino | 供電是否穩定 |
| 跑步機端少大於 0，序列端沒少 | 模組或跑步機 | 量 ④；比較不同 gap；看錄影是否只動了幾格（被當成長按） |
| 跑步機端少小於 0 | 跑步機多動 | 長按自動連續調速；RF 一個指令被算兩次 |
| 每次固定少 1，而且是第一個 | 第一個指令 | 剛啟動或閒置後，第一下是否沒作用 |
| 可能觸底／觸頂（`possibly_clamped`） | 無法判斷 | 這段的跑步機端數字不能用 |

「少在哪裡」可以從資料看出來。「接著查什麼」只是**可能的原因**，驗證前不能當結論。

## 8. 整理數據的規則

1. 只用完成的輪次（`status = completed`）。
2. 一段算一筆資料。同一段、同一輪的指令常常一起失敗，不能當成互相獨立的次數。
3. 算比例時，分母要對：
   - 序列端少 ÷ 電腦送出（`pc_sent`）
   - 跑步機端少 ÷ Arduino 做了（`arduino_executed`；RUN 對照用 `reported_count`）
4. A 送法的 Arduino 計數是**整輪合計**。一輪裡同時有「指令遺失」和「回覆遺失」時，無法分給各段，該輪各段的序列端少會空白。這時用 `rounds` 檔的整輪數字。
5. 「推算掉包」（`drops`）是用**預定的筆數**算的。段提早結束時，沒送出的指令也算在內。只有送滿的段才能用它。
6. 觸底或觸頂的段：跑步機端數字不用，序列端數字照用。
7. 分條件列出，不要把全部輪次併成一個成功率。
8. 比較光耦和 RF 時，同時寫出實際送出速度。兩者做一個指令的時間不同。
9. 每個條件只有 3 輪，只看得出大差別。沒看到掉包，不能寫「不會掉」。

欄位說明見 [README 的紀錄檔](../README.md#紀錄檔csv)。

## 9. 正式開始前要先試

| 編號 | 做什麼 | 要知道什麼 |
|---|---|---|
| T0 | A 送法跑 40 次、gap 0，錄影，試著讀轉向點。光耦和 RF 各一次 | **面板跟得上嗎？影片讀得出最高點嗎？** 讀不出來，A、B 的做法要改 |
| T1 | 照[台架清單](BenchAcceptance.md) B、C 節檢查板子和連線 | 韌體能不能用 |
| T2 | A 送法 40 次，gap 0 和 10 各跑一輪，比較 `commands` 檔的 `gap_us` | 不同 gap 分不分得出來 |
| T3 | 用手按住面板鍵、遙控器鍵 0.5、1、3、5 秒 | 按多久會變成連續調速 |
| T4 | 手動段每秒送一個，光耦和 RF 各 60 個，看錄影逐個核對 | 慢慢送時會不會掉 |
| T5 | 停 30 秒後送一個，加速、減速各 10 次 | 閒置後第一下是否沒作用 |
| T6 | 手動段選 RUN 對照，gap 0、10、100 ms、1 s 各跑 20 個 | 光耦放開太短時，會不會被當成長按 |

跑步機最高速度是 6.0 km/h（實測確認，2026-11-27；先前記的 12 不正確）。這些項目的依據見[研究筆記](research/burst-stress-test-design.md)。

## 10. 限制與還沒決定的事

**做不到的事**

- A 只知道轉向點和最後速度。同一段裡少一個又多一個，會互相抵銷。
- 轉向點靠人看影片。面板更新如果比指令慢，讀到的最高點可能偏低，看起來像掉包。T0 要先確認。
- 畫面會顯示「預期」數字，可能影響讀數。請照影片上看到的數字輸入。
- 量不到 ④，所以分不出模組和跑步機的責任。
- 面板顯示的是設定速度，不是跑帶的實際速度。
- 只有一台跑步機和一套板子，結果不能推到其他機器。
- A、B 和 RUN 用的是測試韌體。原版系統的行為要靠 C 回答。

**還沒決定**

- 有沒有第二塊 Nano 加 RF 接收模組、邏輯分析儀，可以量 ④。接收器自己也可能漏收，用之前要先校正。
- 時程能否延後（原訂 2026-11-27 做完實驗）。
- gap 要不要加大（看 T2、T6）。
- RUN 對照要不要也改成整輪不停（要改韌體）。
- B 的間隔和 C 的節奏，做之前再確認。
